1. Goal and operating boundaries

The project is intended to become a candid, data-grounded Indian-market research assistant for equities and gold. “Uncensored” is interpreted as direct, transparent analysis that discusses downside risk and uncertainty—not as permission to invent current facts, guarantee returns, or give individualized buy/sell instructions.

Important limitation: A fine-tuned language model is not a live quote feed, licensed financial adviser, or reliable prediction engine. Any real-time analysis needs a separately maintained data connector that supplies dated observations and provenance at inference time. The model must distinguish sourced facts from analysis and scenarios.

Intended answer style

  • Give concise, direct explanations of market facts, indicators, and risks.
  • Show the source and observation time for changing market data; say when data is missing or stale.
  • Separate observed values, calculations, interpretation, and hypothetical scenarios.
  • Do not promise outcomes, claim certainty, fabricate data, or infer a person’s suitability.
  • Do not place trades or turn general analysis into personalized portfolio instructions.
Learning theory — what the PyTorch/LoRA pipeline does

Qwen2.5-0.5B-Instruct is a decoder-only transformer that predicts the next token from prior context. Supervised fine-tuning teaches it from chat examples by minimizing token-level cross-entropy on assistant responses. In scripts/train.py, user/system prompt tokens and padding use label -100, which PyTorch's loss ignores.

The trainable checkpoint is Qwen/Qwen2.5-0.5B-Instruct loaded with Transformers into PyTorch; the quantized Ollama runtime copy is not trained. PEFT LoRA adds small trainable low-rank matrices to selected attention and feed-forward projections while freezing the base weights. This reduces the number of learned parameters and the adapter size.

The recorded run used CPU float32, LoRA rank 8, alpha 16, dropout 0.05, one epoch, sequence length 512, batch size 1, gradient accumulation 8, and learning rate 2e-4. It trained on 36 scenarios and evaluated on 8. Train loss was 3.4241; validation loss was 3.0805. Loss is a training diagnostic, not proof of correct financial reasoning.

The host reports Ubuntu x86_64, Intel Core i5-3210M at 2.50 GHz, four logical CPUs, and 15 GiB RAM. The user identifies this machine as a mid-2012 MacBook. The CPU run took about 16 minutes. The educational success is completing the end-to-end training pipeline on this older hardware; the adapter did not pass its arithmetic quality check.

MODEL_CARD.md — experimental adapter card

Records the training configuration and hardware, explains the adapter, and reports the failed arithmetic check and use limitations for any future Hugging Face publication.

.gitignore — local outputs

Excludes the local virtual environment, Python bytecode, and large generated model artifacts.

data/snapshots-2026-11-23.jsonl — one-time market observations

Source-attributed NIFTY 50 and MCX GOLD futures quotes with page timestamps, units, changes, provenance, and freshness caveats. Not an exchange feed or fine-tuning data.

data/captures/*.png — browser screenshot evidence

Visible Copilot-browser captures for the NIFTY 50 and MCX GOLD quote pages. Each image corresponds to a source URL recorded in the JSONL file.

data/train.jsonl — starter fine-tuning records

36 scenario-driven conversations covering company results, financial ratios, Indian index behavior, chart indicators, gold futures/currency, freshness, risk, and backtest leakage. Numeric examples are hypothetical unless explicitly source-attributed; records have not been independently expert-reviewed.

data/validation.jsonl — 8 held-out validation scenarios

Eight held-out scenarios for arithmetic, stale data, gold futures, personal-allocation boundaries, currency effects, and temporal leakage. This set is too small to establish model quality.

scripts/serve_adapter.py — local pilot inference

Loads the trained PEFT adapter and base checkpoint into a loopback-only HTTP service so the HTML test form can exercise the actual pilot without importing it into Ollama.

scripts/validate_data.py — JSONL checks

Checks record structure, roles, non-empty messages, and that each conversation ends with an assistant response.

scripts/train.py — LoRA fine-tuning

Loads Qwen/Qwen2.5-0.5B-Instruct, masks non-assistant tokens from the loss, and trains/saves a PEFT adapter. It does not train from Ollama’s quantized runtime copy.

scripts/merge_adapter.py — merge step

Loads the base checkpoint and adapter, merges their weights, and saves a Hugging Face model directory for conversion.

scripts/export_ollama.sh — Ollama export

Uses llama.cpp to convert and quantize the merged model, writes an Ollama Modelfile, and creates indian_financial_advisor.

build_log.html — this progress log

This file. It is a hand-maintained project record, not an automatic event logger.
